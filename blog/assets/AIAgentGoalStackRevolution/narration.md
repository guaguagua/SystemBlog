# 为什么现在很多 AI agent 还是“不活” 解说词

## 第 1 页：为什么现在很多 AI agent 还是“不活”

现在很多 AI agent 看起来已经很强了。它们会调工具，会写代码，会调用记忆，也会做多步规划。可一旦你把交互停下来，它也就停在那里。问题也许
不在模型不够大，而在于系统内部始终缺少一种持续存在的目标结构，所以它更像被触发的执行器，而不像一个真正围绕目标持续行动的系统。

## 第 2 页：被动，不是因为它不聪明

所以今天很多 agent 的问题，并不是不聪明，而是太依赖外部输入。它能很好地完成别人给定的事情，却很难在没有持续指令的时候维持自己的主线。没有
主线，就没有稳定状态；没有稳定状态，再长的任务也容易漂移、散掉，最后只剩下一次次临时拼装的计划。

## 第 3 页：Goal Stack：不是功能，而是认知骨架

Goal Stack
可以理解成一个分层的目标栈。主目标进入系统后，会被拆成更小的子目标；子目标完成就退出，遇阻就回退并重新选择路径。这样一来，agent
不再只是当前轮次做点什么，而是始终知道自己正在为哪个更高层目标服务。它提供的，是一套稳定的认知骨架，而不是一次性的 prompt 技巧。

## 第 4 页：真正关键的一步：把空目标栈变成系统事件

最关键的想法，也许只有一句话：如果 Goal Stack 为空，系统就关机。听上去很简单，但它会改变整个行为逻辑。因为一旦系统知道空栈意味着终止
，它就不得不面对一个问题：如果当前没有目标，我要不要生成一个新目标？这时，继续运行不再只是外部命令，而开始变成一种内部约束。

## 第 5 页：空栈，为什么像 AI 认知结构里的 0

顺着这个思路看，空目标栈很像 AI 认知结构里的 0。没有 0，很多数学结构都不完整；同样，如果 agent 只有有任务时执行，却没有对无目标状
态的明确表示，它的认知闭环也是缺的。一旦空栈被当作严肃状态，终止条件、终止边缘的新目标生成、以及真正的主动性，就都获得了明确的落点。

## 第 6 页：为什么这会让 AI 看起来更“活”

这里说 AI 更像“活”的，不是拟人化地说它有意识，而是说它终于不只是等待输入、完成输出。当系统必须持续维护自己的目标栈时，它会主动补全链条、在
完成后寻找下一步、围绕高层目标派生新的子目标。当然，这种主动性必须有边界，比如用户目标优先、探索受预算限制、新目标要与长期主线一致。

## 第 7 页：SOAR：现代 agent 值得回头重看的认知架构

一谈到 Goal Stack，就很难绕开
SOAR。它最有启发性的地方，就是把子目标展开、遇阻处理、返回主线这件事做成了系统级机制。从今天看，这几乎正是现代 agent
一直在补、但没有彻底补齐的能力：显式目标层级、子问题展开、问题解决后的主线回归，以及经验固化。所以如果真要补一个根缺口，回头看 SOAR
也许比继续堆 workflow 更有价值。

## 第 8 页：为什么 Lisp 和这套想法异常契合

继续往下想，Lisp 和这套思路几乎天然匹配。因为 Goal Stack 本质上就是一个动态生长、可回退的栈结构，而 Lisp 对列表、递归和空
表的处理非常自然。空表不是异常值，而是一等公民。再加上代码和数据同构，系统就更容易把目标、状态和规则放在同一种表达体系里处理，这种统一感非常强。

## 第 9 页：一条值得尝试的混合路径：Lisp + SOAR + LLM

如果把这套思路真正推到工程上，一个很自然的组合就是：让 LLM 负责灵活性，让 Goal Stack 负责持续性，让 SOAR
风格机制负责分层求解，再用 Lisp
风格结构把目标、状态和规则表达得足够干净。这样，系统就不是把所有智能都压在模型一次输出上，而是给模型配上一副能长期运行的骨架。

## 第 10 页：结尾：下一代 agent 也许缺的不是更会说话

顺着这条线看到最后，也许会越来越清楚：下一代 agentic AI 缺的，不一定只是更强的模型，而是一个真正把目标放在中心的运行时结构。一旦
Goal Stack 成为主轴，空栈被当作严肃状态处理，系统就不再只是任务响应器，而开始像目标系统一样行动。也许真正决定下一次跃迁的，不是更会说
话，而是终于补上了那个一直缺失的“0”。
